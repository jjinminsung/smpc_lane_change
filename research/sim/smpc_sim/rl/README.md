# 트리 잎의 가치함수 V (강화학습 부분)

트리 플래너는 8 초(40 스텝) 앞까지만 본다. 8 초 뒤 자차가 "차선 끝에 갇힐 자리"에 있는지,
"다음 차선 변경을 바로 할 수 있는 자리"에 있는지는 트리 안에서 알 수 없다. 그 판단을 배운 함수가 V 다.

```
루트 a0 의 값 = min_c Σ_j p_j [ J_j(a0, c_j) − λ · V(x_N,j) ]   s.t.  Σ_j p_j r_j(k) ≤ ε (모든 k)
```

## 파일 순서대로 읽기

| 파일 | 내용 | RL 개념 |
|---|---|---|
| `features.py` | 상태 → 16 차원 벡터. 자차 속도, 차선, 차선 끝까지 거리, 같은/다음 차선 앞뒤 차와의 간격·상대속도 | 상태 표현 (state representation) |
| `reward.py` | 성공 +1, 실패 −1, 충돌 −10, 차선 끝 정지 −0.2, 시간 −0.01/s, 할인율 γ = 0.98/s. 리턴 G_t 계산 | 보상 설계, 할인 리턴 |
| `value.py` | 16 → 64 → 64 → 1 MLP (tanh). 트리에서는 λ·V 로 비용 단위로 바꾼다 | 함수 근사 (function approximation) |
| `train_value.py` | 근사 정책 반복: 돌리기 → 리턴 모으기 → V 회귀 → 새 V 로 다시 돌리기 | 정책 평가 / 정책 개선 |

## 학습 루프에서 일어나는 일

1. **정책 평가 (policy evaluation).** 지금 정책(트리 + V_k)으로 에피소드 300 개를 돌린다.
   0.5 s 마다 상태 특징 s_t 를 남기고, 에피소드가 끝나면 그 뒤에 실제로 받은 보상을 할인해 더해
   G_t 를 만든다(몬테카를로 리턴). V_0 = 0 은 "V 없는 트리"다.
2. **회귀.** V(s) ≈ E[G | s] 를 MSE 로 맞춘다. 지난 바퀴 데이터도 버리지 않고 함께 쓴다.
   검증은 에피소드 단위로 떼어 낸다(같은 에피소드 샘플끼리는 닮아서, 샘플 단위로 떼면 과적합을 못 본다).
   로그의 `const_mse`(평균값 하나로 예측) 보다 `val_mse` 가 작아야 V 가 뭔가를 배운 것이다.
3. **정책 개선 (policy improvement).** 트리가 잎에서 새 V 를 쓰면, 같은 위험 안에서 "나중이 좋은" 루트를
   고른다. 이게 새 정책이다. 1 로 돌아간다.

AlphaZero 의 "탐색 + 학습된 가치"와 같은 구조다. 다만 여기서는 탐색(트리)이 이미 좋은 정책이고,
V 는 탐색이 못 보는 지평선 너머만 메운다.

## 정할 것과 지금 값

| 항목 | 지금 값 | 바꾸면 |
|---|---|---|
| λ (보상 1 = 비용 몇 점) | 검증 시드에서 {10, 30, 60} 중 선택 | 크면 V 를 더 믿는다. 너무 크면 위험 비용(80·risk)을 V 가 덮는다 |
| γ | 0.98 / s | 1 에 가까울수록 먼 성공까지 본다. 분산이 커진다 |
| 리턴 | 몬테카를로 | TD(λ) 로 바꾸면 분산이 줄고 편향이 생긴다 |
| 반복당 에피소드 | 300 | 많을수록 V 가 정확하다 |
| 시드 분리 | 학습 10000+, λ 검증 5000+, 최종 비교 2000+ | 최종 비교 시드로 λ 를 고르면 결과가 낙관적으로 나온다 |

## 한계 (보고서에 적을 것)

- V 는 시뮬레이터 NPC(실측 분포 + IDM)에서 배운 근사다. MORAI·실제 운전자에게 그대로 옮겨진다는 보장은 없다.
- 잎 특징은 판단 시점의 대표 차량(앞·목표 차선 앞뒤)만 쓴다. 합류 뒤 "그다음 차선"의 차량은 잎에서 모른다
  (트리가 그 차량들을 예측하지 않기 때문). 실제 상태 특징도 같은 범위로 맞춰 일관성을 지켰다.
- 안전은 V 가 아니라 위험 제약(Σ p r ≤ ε)이 맡는다. V 는 비용에만 들어간다.
